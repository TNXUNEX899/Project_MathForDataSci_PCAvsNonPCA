# Credit Scoring Model Comparison: Logistic Regression vs. XGBoost (Before & After PCA)

## ภาพรวมโปรเจกต์
โปรเจกต์นี้มุ่งเน้นการเปรียบเทียบประสิทธิภาพของโมเดล Machine Learning ระหว่าง Logistic Regression และ XGBoost ในการทำนายความเสี่ยงการผิดนัดชำระหนี้บัตรเครดิต โดยศึกษาผลกระทบของการจัดการปัญหาข้อมูลไม่สมดุล และการลดมิติข้อมูลด้วยเทคนิค Principal Component Analysis (PCA) ที่ระดับความแปรปรวนสะสม $\ge 90\%$ เพื่อประเมินความสมดุลระหว่างความแม่นยำในการทำนายและต้นทุนเวลาในการประมวลผล

## การวิเคราะห์

### 1. การเปรียบเทียบประสิทธิภาพระหว่างโมเดล (Logistic Regression vs. XGBoost)
* **ความสามารถในการจำแนกกลุ่มลูกค้า (ROC-AUC & F1-Score):** XGBoost (Before PCA) มีประสิทธิภาพโดยรวมสูงสุดด้วยค่า ROC-AUC 0.7578 และ F1-Score 0.5186 ซึ่งสูงกว่า Logistic Regression อย่างชัดเจน สะท้อนให้เห็นว่าพฤติกรรมการชำระหนี้และยอดบิลย้อนหลัง 6 เดือนมีความสัมพันธ์แบบไม่เป็นเส้นตรง (Non-linear) และมีความซับซ้อน (Feature Interactions) ซึ่งโมเดลกลุ่ม Tree-based สามารถจับรูปแบบได้ดีกว่าโมเดลเชิงเส้น
* **การจัดการ Class Imbalance และ Trade-off ของค่า Recall vs. Precision:**
  * Logistic Regression (`class_weight='balanced'`) ให้ค่า Recall สูงสุด (0.6252) สามารถตรวจจับกลุ่มลูกค้าที่มีความเสี่ยงเบี้ยวหนี้ได้ครอบคลุมกว่า แต่ต้องแลกมากับค่า Precision ที่ต่ำ (0.3741) ซึ่งหมายถึงการเกิด False Positive (ทายว่าลูกค้าดีจะเบี้ยวหนี้) ในสัดส่วนที่สูง
  * XGBoost (`scale_pos_weight`) รักษาสมดุลได้ดีกว่า แม้ค่า Recall จะอยู่ที่ 0.5822 แต่ให้ค่า Precision สูงกว่ามาก (0.4676) และดันค่า Accuracy รวมขึ้นไปถึง 76.09% ลดปัญหาการปฏิเสธสินเชื่อลูกค้าชั้นดีโดยไม่จำเป็น

### 2. ผลกระทบของการลดมิติข้อมูลด้วย PCA (Before vs. After PCA)
* **การประหยัดทรัพยากรและเวลา (Training Speed):** การใช้ PCA ลดมิติข้อมูลลงเกือบครึ่ง (จาก 23 เหลือ 13 Components) ช่วยลดเวลาในการเทรนโมเดลได้อย่างมีนัยสำคัญ โดย Logistic Regression เทรนเร็วขึ้น ~4 เท่า (จาก 0.2329 วินาที เหลือ 0.0578 วินาที) และ XGBoost เทรนเร็วขึ้น ~2.27 เท่า (จาก 1.4123 วินาที เหลือ 0.6225 วินาที)
* **การสูญเสียสารสนเทศสำคัญของ XGBoost:** หลังทำ PCA ค่า ROC-AUC ของ Logistic Regression ลดลงเพียงเล็กน้อย (-0.0086) แต่ XGBoost ลดลงถึง -0.0293 (จาก 0.7578 เหลือ 0.7285) และค่า Recall ลดลงจาก 0.5822 เหลือ 0.5445 สาเหตุหลักเกิดจากการที่ PCA แปลงแกนข้อมูลเดิมให้ตั้งฉากกัน (Orthogonal Transformation) ทำให้ความหมายเชิงพฤติกรรมเฉพาะตัวของฟีเจอร์สำคัญ (เช่น สถานะการชำระเงินล่าช้าในเดือนล่าสุด `PAY_0`) ถูกเฉลี่ยรวมเข้ากับฟีเจอร์อื่น ส่งผลให้การแบ่งโหนด (Splitting) ของ Decision Tree ใน XGBoost เสียความแม่นยำลง

### 3. ข้อสรุปและการนำไปประยุกต์ใช้ในธุรกิจสินเชื่อ (Business Implications)
* **กรณีเน้นความแม่นยำสูงสุดและอธิบายผลได้ (Production Credit Scoring):** แนะนำให้ใช้ XGBoost (Before PCA) เนื่องจากให้ค่า ROC-AUC และ Precision สูงสุด อีกทั้งยังคงโครงสร้างฟีเจอร์ดั้งเดิมไว้ ทำให้สามารถทำ Feature Importance หรือ SHAP Values เพื่ออธิบายเหตุผลในการอนุมัติ/ปฏิเสธสินเชื่อตามเกณฑ์กำกับดูแลของสถาบันการเงินได้
* **กรณีระบบที่ต้องการความรวดเร็วสูงหรือข้อมูลมีมิติใหญ่มาก:** การใช้ PCA ร่วมกับ Logistic Regression เป็นทางเลือกที่คุ้มค่าในเชิงวิศวกรรม เพราะสูญเสียความแม่นยำน้อยมากเมื่อเทียบกับความเร็วในการประมวลผลที่เพิ่มขึ้นหลายเท่าตัว
